# DesignEverything 8.1.0 — Interactive Question Cards

**Status**: **RELEASE CANDIDATE — feature-complete, awaiting live R-spike confirmation**  
**Cut date**: not recorded — live R-spike outstanding (see Known limitations)  
**Schema**: interview-script 2.1.0

## What shipped

- Claude Code renders native `AskUserQuestion` cards for 14 static-catalog questions (2–4 choices
  each, one optionally marked recommended) and 5 grounded three-choice hint questions. A user can
  always select the host-provided Other option or type free text.
- The committed answer is always the option's derived prose (`label: description`), never the
  internal machine token — Core owns this via `deriveAnswerText` so Claude's cards and the
  AGENTS.md text fallback can never independently drift on wording (D53/D58).
- script.yaml is the single source of truth; the AGENTS.md fallback text is generated from the
  same data and the same `deriveAnswerText` function.
- The core carries an immutable committed-answer snapshot with the prompt capability so hint
  rendering does not infer answers from model memory.
- Codex plugin installation ships a dedicated text-only skill (`adapter/codex-plugin/skills/design-everything/SKILL.md`).
  It does not claim native cards or a `UserPromptSubmit` capability.
- `ConformanceMatrix.md` publishes the `interactive_choice` capability per harness: Claude Code
  native, AGENTS.md text degradation, Cursor/Antigravity/Windsurf deferred.

## Compatibility and migration

All fields are additive: scripts without `options`, `recommendation`, or `option_hints` remain
free-text, unchanged. Copy `Design/Adapters/generated/AGENTS.sample.md` to a repository-root
`AGENTS.md` when using a generic rules-only agent. `.agents/AGENTS.md` is legacy and not a
discovery path.

## Evidence and metrics (measured, not modeled)

Measured by [test/journey/interactive-cards-turn-count.test.ts](../../test/journey/interactive-cards-turn-count.test.ts)
walking the real canonical web journey (`CAL0, S0–S7, R1, S8, W1–W5`, 16 questions) through the
real state machine (`commitStep`/`issueTurnCapability`), not a hand-typed ID list. Full methodology
and the corrected-vs-earlier-guess note: [interactive-cards-turn-count-report.md](evidence/interactive-cards-turn-count-report.md).

- 16 questions total, 16 commits (D54 — one human turn = one commit, unchanged by this lane).
- 11 card-assisted questions (`CAL0, S1–S5, S7, W1–W4`), 5 free-text questions (`S0, S6, R1, S8, W5`).
- **Baseline (pre-8.1): 32 typed messages** — every question needed one typed answer plus one typed
  confirmation (`InteractiveQuestionCardsPlan.md` §1).
- **After 8.1: 5 typed messages** — the translate-back confirmation is now always a 3-choice card
  (`Đúng rồi`/`Sửa lại`/`Giải thích thêm`) for every question, including the 5 free-text ones; only
  a free-text question's *answer* still requires typing.
- **84% reduction** in typed messages on the canonical (non-Other, non-timeout) path.

An earlier draft of this note (written before B22e's measurement existed) guessed "16 keyboard
submissions" — that number was wrong, conflating total commit turns (16, unchanged) with typed
messages specifically (5). The 84%/5 figure above is the corrected, measured value.

## Known limitations at RC

- **R-spike not yet run live — the one thing blocking GA.** Whether Claude Code's `UserPromptSubmit`
  hook fires when a user answers via a card (vs. types free text) has not been confirmed in a real
  session. B22c's code currently implements the "commit within the same turn, no cross-turn
  retention" branch as its working assumption; if a live run disproves it, B22c needs a follow-up
  patch for a hold-across-turns mechanism. The probe is already built and ready to run —
  `E:\rspike-8.1-probe`, installed for real via `install.mjs` (see
  [r-spike-userpromptsubmit-probe.md](../ContractForAI/Core/v7-expansion/r-spike-userpromptsubmit-probe.md) §7
  for exact steps). This is the only reason this note is not cut GA yet.
- `test/regression/golden-web.test.ts` checks emitted doc structure against hardcoded answers fed
  straight into `emitTree()`; it never calls `commitStep`, so it has no concept of a "turn" to
  count. Turn measurement lives in the separate journey test above, not an extension of golden-web.
- Codex/AGENTS.md receive the same option catalog as text only — no native card surface; see
  `ConformanceMatrix.md`'s `interactive_choice` column, which publishes this gap rather than
  promising parity (D37).
- The 84% reduction is measured on the canonical non-Other, non-timeout path only. A user who picks
  Other on a card-assisted question falls back to typing for that question, same as before.
